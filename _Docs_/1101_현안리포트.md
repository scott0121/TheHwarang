## 2. 치명적 격차 (Release Blocker)

> 아래 항목은 하나라도 비어 있으면 Steam 출시 또는 최소한의 평가(리뷰)를 통과할 수 없습니다.

### B-1. 오디오 시스템 부재 — **심각도 S**
- 프로젝트 내 `.wav/.ogg/.mp3`(플러그인 제외) **0개**. `AudioMixer` 없음.
- 유일한 사운드는 `MonsterAI.PlayImpactSound`, `RollingBoulder.PlayShatterSound`의 **런타임 `AudioClip.Create` 합성음**이며, 생성한 클립을 파괴하지 않아 누수 요인이기도 합니다.
- 패링/반사가 핵심인 게임에서 **히트 피드백 사운드 없음 = 손맛 검증 불가**.
- **필요**: `AudioManager`(SFX/BGM/UI 버스, 풀링된 AudioSource, 우선순위/동시재생 제한), `AudioMixer` 3버스+볼륨 설정 연동, 이벤트 기반 호출(`OnParry`, `OnHit`, `OnShoot` 등).

### B-2. UI 전면 IMGUI — **심각도 S**
- `OnGUI()` 사용 9개 파일: `IntroOutgameManager`, `StageClearUI`, `BossHealthBarUI`, `ChargeIndicatorUI`, `MonsterHealthBarManager`, `ScreenDamageVignetteUI`, `ProgressionDebugUI`, `HelperCompanion`, `MonsterTestController`.

- **필요**: UGUI(TextMeshPro) 또는 UI Toolkit 중 **하나로 확정**하고, HUD/메뉴/팝업을 프리팹 기반으로 이관. 패드/키보드 포커스 내비게이션 필수.

## 3. 기술 부채 및 구조 문제

### T-1. `MonsterAI.cs` God Class (3,632줄) — 우선순위 P0
- 1024 평가에서 3,457줄 → 현재 3,632줄로 **오히려 증가**. 파일 내 `GetComponent<`/`Find*`/`Camera.main` 등 호출이 약 50회로 단일 파일 최다.
- `Monsters/*Behavior`로의 분리가 시작됐지만 **이중 구현(MonsterAI 내부와 Behavior 클래스에 동일 로직)**이 남아 있습니다(1028 문서 지적). 신규 몬스터 추가 시마다 어느 쪽이 실제 실행되는지 추적해야 합니다.
- **제안**: 전략 패턴 완성(공통 `IMonsterBehavior` + 상태 머신), `MonsterAI`는 오케스트레이션(상태 전이, 타깃팅)만 담당. 목표 800줄 이하. 리팩터링 전에 **몬스터 13종 회귀 테스트 씬(`MonsterTest`) 자동화**를 먼저 만들 것.

### G-3. 메타 루프(죽음→복귀→성장) 완성 — P0
- 데이터 구조(`memoryShards`, `wellBowLevel` 등 4계열, 핵심 기억, `retryBlessingStacks`)는 있으나 **UI·밸런스·획득처의 연결이 닫히지 않았습니다**. 1024 보고서의 "메타 루프가 비어 있다"는 평가는 현재도 유효합니다.
- `IntroOutgameManager`에서 성장 결과(1-1~6-2 핵심 기억)가 `PlayMainSceneController.ApplyOutgameShrineUpgradesToPlayer`에 **일부(4종)만 반영**됩니다. 다시 말해 보상 중 일부는 선택해도 효과가 없는 **"죽은 보상"**입니다.
- **필요**: 보상 테이블(획득처 × 소모처) 정합성 시트, 효과 적용 누락 점검 자동 테스트(모든 핵심 기억/노드가 실제 스탯에 반영되는지 검증하는 테스트).

### G-4. 로그라이크 반복성 부족
- 인런 Boon 12종, 룸 템플릿 수, 몬스터 구성 변이가 제한적. 기획 평가 5/10.
- 제안: Boon 간 시너지 태그, 룸 이벤트(상점/제단/함정/엘리트), 런별 변수(저주/축복 모디파이어), 시드 공유/데일리 챌린지(후순위).

### G-5. 난이도/밸런스 파이프라인 부재
- 난이도 선택, 접근성 옵션(피격 감소, 패링 윈도 확대), 밸런스 시뮬레이션(헤드리스 전투 시뮬) 없음.
- 최소 3단계 난이도와 "스토리 모드"가 서사 중심 게임의 이탈률을 크게 줄입니다.

### G-6. 튜토리얼/온보딩 부재
- 조작 안내는 문서/디버그 패널에 있고 인게임 튜토리얼은 없음. 기획서의 튜토리얼 보스는 미구현. 패링/차징은 숙련이 필요하므로 **첫 10분 설계가 리뷰를 좌우**합니다.

### G-7. 헬퍼 시스템
- 독창적 아이디어이나 `HelperCompanion`(675줄)은 IMGUI 의존 요소가 있고, 보석 수거 AI가 위험 구역을 회피하는지 검증된 증거가 없습니다. 레벨업 템포에 직접 영향을 주므로 **밸런스 테스트 항목 1순위**.

## 9. 결정이 필요한 사항 (Open Decisions)

1. **UI 프레임워크**: UGUI+TMP vs UI Toolkit (권고: 인게임 HUD는 UGUI, 이미 프리팹 파이프라인과 PrimeTween/UIParticle이 UGUI 기반)
2. **출시 형태**: 데모 → 얼리액세스(권고) vs 정식 출시
3. **지원 언어와 패드 목표**: 영어/중국어 간체/일본어 동시 vs 순차, Steam Deck "Playable" 목표 여부
4. **팀 규모와 일정**: 위 로드맵은 1인 풀타임 기준. 인원이 다르면 재산정 필요
5. **Unity 버전 고정**: 6000.6.x 유지 vs LTS 이동 (패키지 호환성 평가 필요)
6. **버전 관리/에셋 정책**: Git+LFS vs Plastic/Perforce

## 11. 맺음말

이 프로젝트의 자산은 **명확한 전투 판타지(활 카이팅+단검 반사), 독창적 IP, 상당한 구현 속도**입니다. 약점은 아이디어가 아니라 **"출시 가능한 제품이 되기 위한 지루한 부분"** 이 전부 미착수라는 점입니다. 지금 시점에서 가장 위험한 행동은 **콘텐츠(몬스터/스테이지) 추가를 계속하는 것**입니다. 기반(UI, 오디오, 입력, 로컬라이제이션, 빌드/테스트)이 없는 채 콘텐츠를 늘리면 나중에 전량 재작업됩니다.
